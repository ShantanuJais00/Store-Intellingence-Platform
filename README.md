Store Intelligence Platform is an end-to-end Computer Vision and Analytics solution designed for physical retail environments. It captures real-time video feeds from CCTV cameras, processes them using state-of-the-art deep learning models (YOLOv8, ByteTrack, OSNet) to detect and track individuals across multiple cameras, and generates actionable insights such as store footfall, conversion rates, zone dwell times, and anomaly detection. These insights are exposed via a robust async FastAPI backend and visualized on a React-based dashboard.

## Quick Start (Docker)

The fastest way to get the entire stack (API, PostgreSQL, Dashboard) running is using Docker Compose:

```bash
docker compose up -d
```

What happens:
1. **PostgreSQL** spins up with the `store_intelligence` database.
2. The **API** container runs Alembic migrations and starts the FastAPI server on port 8000.
3. The **Dashboard** container serves the React frontend on port 3000.

## Manual Setup

### 1. Requirements
- Python 3.11+
- Node.js & npm (for dashboard)
- PostgreSQL 16

### 2. Backend Setup
```bash
# Create virtual environment
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Setup Database
export DATABASE_URL="postgresql+asyncpg://postgres:postgres@localhost:5432/store_intelligence"
alembic upgrade head

# Run API
uvicorn app.main:app --reload
```

## Running the CV Pipeline

The Computer Vision pipeline runs separately from the web API. It processes video files or RTSP streams and pushes events to the API.

```bash
python -m cv.run_pipeline \
    --video path/to/camera1.mp4 \
    --store-id store_01 \
    --camera-id cam_01 \
    --camera-type entry \
    --api-url http://localhost:8000
```

## API Documentation

Once the server is running, interactive API docs are available at `http://localhost:8000/docs`.

All endpoints are prefixed with `/api/v1`.

### Health

- **GET `/api/v1/health`**
  System health check including database connectivity and feed staleness detection.
  ```bash
  curl http://localhost:8000/api/v1/health
  ```
  Response:
  ```json
  {
    "status": "ok",
    "db_status": "ok",
    "last_event_timestamp": "2026-03-08T18:15:31.840000",
    "stale_feed_warning": false,
    "version": "1.0.0"
  }
  ```

### Ingestion

- **POST `/api/v1/events/ingest`**
  Ingest a batch of events generated by the CV pipeline. Automatically creates visitor sessions.
  ```bash
  curl -X POST "http://localhost:8000/api/v1/events/ingest" \
       -H "Content-Type: application/json" \
       -d '{"events": [{"event_id": "e1", "timestamp": "2026-03-08T18:10:05Z", "event_type": "ENTRY", "store_id": "ST1076", "camera_id": "cam1", "visitor_id": "V001"}]}'
  ```
  Response:
  ```json
  {"accepted": 1, "rejected": 0, "errors": []}
  ```

- **POST `/api/v1/events/batch`**
  Alias for `/events/ingest` — accepts the same payload and returns the same response.

- **POST `/api/v1/transactions/ingest`**
  Ingest POS transactions and automatically correlate them with visitor sessions.
  ```bash
  curl -X POST "http://localhost:8000/api/v1/transactions/ingest" \
       -H "Content-Type: application/json" \
       -d '[{"store_id": "ST1076", "order_id": "ORD001", "timestamp": "2026-04-10T12:15:05", "product_id": "P001", "brand_name": "Brand A", "total_amount": 599.0}]'
  ```

### Metrics

- **GET `/api/v1/stores/{store_id}/metrics`**
  Retrieve high-level KPIs: unique visitors, conversion rate, average dwell per zone, queue depth, and abandonment rate.
  ```bash
  curl "http://localhost:8000/api/v1/stores/ST1076/metrics"
  ```
  Response:
  ```json
  {
    "unique_visitors": 3,
    "conversion_rate": 0.166,
    "avg_dwell_per_zone": {"PURPLLE_MUM_1076_Z01": 33440.0},
    "queue_depth": 0,
    "abandonment_rate": 0.333
  }
  ```

### Funnel

- **GET `/api/v1/stores/{store_id}/funnel`**
  Get retail conversion funnel: Entry → Zone Visit → Billing → Purchase, with drop-off percentages at each stage.
  ```bash
  curl "http://localhost:8000/api/v1/stores/ST1076/funnel"
  ```
  Response:
  ```json
  {
    "stages": [
      {"name": "ENTRY", "count": 3, "dropoff_pct": 0.0},
      {"name": "ZONE_VISIT", "count": 3, "dropoff_pct": 0.0},
      {"name": "BILLING", "count": 3, "dropoff_pct": 0.0},
      {"name": "PURCHASE", "count": 1, "dropoff_pct": 66.7}
    ]
  }
  ```

### Heatmap

- **GET `/api/v1/stores/{store_id}/heatmap`**
  Zone-level traffic heatmap with visit frequency, average dwell time, normalized scores, and data confidence.
  ```bash
  curl "http://localhost:8000/api/v1/stores/ST1076/heatmap"
  ```
  Response:
  ```json
  {
    "zones": [
      {
        "zone_id": "PURPLLE_MUM_1076_Z01",
        "frequency": 1,
        "avg_dwell_ms": 33440.0,
        "normalized_score": 33.3,
        "data_confidence": "low"
      }
    ]
  }
  ```

### Anomalies

- **GET `/api/v1/stores/{store_id}/anomalies`**
  Detect operational anomalies such as dead zones (no activity for 30+ minutes), long queues, and unusual crowd patterns.
  ```bash
  curl "http://localhost:8000/api/v1/stores/ST1076/anomalies"
  ```
  Query Parameters:
  - `severity` (optional): Filter by severity (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`)
  - `hours_back` (optional, default: 24): Look-back window in hours

### Sessions

- **GET `/api/v1/stores/{store_id}/sessions`**
  List paginated visitor sessions with entry/exit times, zones visited, dwell time, and conversion status.
  ```bash
  curl "http://localhost:8000/api/v1/stores/ST1076/sessions?limit=50&offset=0"
  ```

- **POST `/api/v1/stores/{store_id}/sessions/build`**
  Manually trigger session construction from raw events for a given store and date.

### WebSocket

- **WS `/ws`**
  Real-time event stream. The dashboard connects here to receive live event updates as they are ingested.

## Environment Variables

| Variable | Description | Default |
|----------|-------------|---------|
| `DATABASE_URL` | Async PostgreSQL connection string | `postgresql+asyncpg://postgres:postgres@postgres:5432/store_intelligence` |
| `YOLO_MODEL` | YOLOv8 model weights file | `yolov8n.pt` |
| `YOLO_CONFIDENCE` | Confidence threshold for object detection | `0.4` |
| `REID_THRESHOLD` | Similarity threshold for cross-camera person matching | `0.7` |
| `LOG_LEVEL` | Application logging level | `INFO` |
